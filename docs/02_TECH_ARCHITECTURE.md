# 02 — Technical Architecture

Status key: **[D]** decided, **[P]** proposed, **[O]** open.

## 1. Engine and languages
- **Engine: Godot 4.x, version pinned at the start of M0 (D-036)** **[D]**. Reasons: all project files are text (scenes `.tscn`, resources `.tres`, scripts), so agents can read/diff/edit them; runs headless from CLI for tests and screenshots; light; free; good Steam support through GodotSteam.
- **Language: GDScript** for gameplay and tools inside Godot **[P]**. Static typing required (`var x: int`, typed function signatures).
- **Performance escape hatch:** if profiling proves GDScript cannot hit budgets, move only the hot loop (horde simulation) to a **GDExtension in Rust or C++** **[P]**. Do not do this before a profile shows the need. M1 measured no need yet; the triggers to revisit are in `reports/perf_m1.md` section 6.
- **Tooling language:** Python 3 for tools (`/tools`): asset forge, validators, balance runner **[P]**.
- Alternative considered: Bevy (Rust). Rejected for now: slow compiles, fast-changing API, no editor.

## 2. Rendering approach **[P]**
- 3D scene with an **orthographic isometric-style camera** and **billboarded sprites** (2.5D). Gameplay happens on a flat ground plane (x, z).
- **Horde rendering:** one `MultiMeshInstance3D` per enemy type/atlas, updated from packed arrays. **Never one Node per enemy.** As built (D-087, D-120): `view/horde_renderer.gd` owns one MultiMesh per enemy type in the catalog plus one per tower type, one for husks and one for bare (M1 bench) towers; `view/horde_batcher.gd` (RefCounted, tested headless) packs the visible instances each frame into one `PackedFloat32Array` per batch (TRANSFORM_3D with identity basis + 4 custom floats: frame offset, flip, hit flash, tint flag), uploaded in bulk with `visible_instance_count` set to the visible count. Off-screen culling is done on the CPU in the fill loop (ground point against the orthographic view rectangle grown by the sprite height); each MultiMesh has a fixed `custom_aabb` over the sim area, so Godot never recomputes it. `last_fill_usec` records the fill + upload time (diagnostics). Placeholder sprites are generated at runtime by `view/placeholder_art.gd`; sprite heights (world units), walk frames and fps are in `data/render/*.json` (schema `tools/schemas/render.schema.json`), placeholders until CP-M1; per-type values move to sprite metadata in M4. **Looks and combat feedback (D-120):** `enemy_looks` (by archetype: shape, colour, height scale; bosses bigger) and `tower_looks` (by attack kind, plus `husk` and `bare`) in the render data pick the placeholder shape per batch; D-163 gives the M3 kinds their own shapes (`wall` wide low block, `aura` orb with a halo, `repair` body + cross, `mark` body + target dot, `slow_area` wide body + 2 orbs). **Tint (D-163):** custom float `a` = 1 mixes the batch's `tint` uniform colour by its alpha: enemies while marked (`mark_until > clock`, `fx.mark_tint`), every tower while Crescendo lasts (`clock < haste_until`, `fx.haste_tint`). The batcher skips corpses (`hp <= 0`, still in the arrays until DEATHS) and sets the flash flag while `world.tick - hit_tick <= ceil(flash_sec / SIM_DT)`; the billboard shader mixes the sprite to white. **FX layer:** `view/fx_pool.gd` (`FxPool`, RefCounted, tested headless) turns the events of every step into effects (SoA: kind, start, end, age, life, colour, size), read through `SimDriver.on_step`: `ENEMY_DIED` -> puff (type look colour and size) and, with gold, a coin flying to the Guardian (D-094, cosmetic); `TOWER_FIRED` -> shot ribbon from the tower (by uid, skipped if gone) to the target (D-098); `GUARDIAN_HIT` -> Guardian flash, plus a ribbon from a ranged attacker; `TOWER_HIT` -> spark at the tower; `SKILL_USED` of an area blast or Tangle -> ring growing to `skill_radius` (blast or snare colour), of Emergency Rebuild -> ring to `fx.rebuild_radius`; `TOWER_REPAIRED` -> beam ribbon from the repairer to the healed tower (by uid, skipped if gone) or to the Guardian (D-163); `ENEMY_HIT` spawns nothing (the flash covers it, thorns included). **State overlays (D-163):** `view/fx_overlays.gd` (`FxOverlays`, RefCounted, tested headless) is rebuilt from the world every frame (own cap, empty with no run): a relationship marker disc above every live tower with `syn_mask != 0`, a ring of radius `reach` around every live aura tower, a gold ring at the Guardian while `clock < bounty_until`. Effects age in view seconds and are capped at `fx.max_effects` (new ones dropped when full). `view/fx_layer.gd` (`FxLayer`, a node in `main.tscn`) draws them: discs (puffs, coins, sparks) in one MultiMesh with `fx.gdshader`, ribbons, beams and rings (effects and overlays) in one `ImmediateMesh` rebuilt per frame, the overlay markers in the same disc MultiMesh, a translucent Shield disc while `clock < shield_until and shield_left > 0`, a Stand Firm disc while `clock < guard_until`, and the Guardian flash. No Node per enemy or per effect. **Main scene:** `game_view.gd` starts IDLE behind the start screen or the hub (`RunFlow.screen`, D-154); a rescue button in the hub queues `StartRun(random seed, "run_m3", Guardian, unlocked, meta nodes)` from the profile (D-125, D-154); no scripted towers, the player builds (D-121); commands only. The bench sets `demo = false` and skips it.
- Waifus/towers (few instances): can be regular nodes with skeletal 2D parts (see `03_ART_PIPELINE.md`).
- Sprite animation for the horde through a shader (`view/billboard.gdshader`, no AnimatedSprite nodes): a camera-facing billboard pivoted at the bottom centre, unshaded, alpha scissor 0.5 (opaque cut-out, no transparency sorting). Per-instance custom data: `r` = frame offset (desynchronises neighbours), `g` = flip (1 when the enemy is right of the Guardian on screen, so it faces the Guardian), `b` = hit flash (D-120), `a` = tint flag (D-163). The frame is `(offset + int(TIME * fps)) % frames`: the walk cycle is cosmetic and stays in the view (the sim's `anim_frame` is not used).
- **Base resolution [D]:** 2560x1440, scaled down to 1280x800 on Steam Deck (D-039).
- **Movable camera [D]:** the player can move the camera (D-040), so the sim world is larger than the screen and the view culls off-screen entities. Controls and bounds: D-041.
- **Camera rig [P]:** `view/iso_camera.gd` is a `Node3D` at the focus point on the ground with a child orthographic `Camera3D` placed by yaw, pitch and distance. Its tunables (angle, distance, the 3 zoom sizes, pan speed, edge-scroll margin, bounds radius + margin) live in `data/camera/*.json` (schema `tools/schemas/camera.schema.json`, D-086). The angle is a placeholder (pitch 30, yaw 45) until CP-M1. It reads no device: `PlayerInput` calls `pan(dir, delta)`, `zoom_step(dir)` and `recentre()`, and reads `focus()`. Its actions are listed in `09_CONTROLS.md`.
- **UI and HUD [P] (D-121):** `view/ui/hud.tscn` + `hud.gd` (`Hud`, a CanvasLayer child of `Main`, `setup(world)` from `game_view`) reads sim state every frame and writes none: Guardian HP bar and `{hp} / {max}` (top left, max = `world.guardian_max_hp`), run clock `m:ss` and the wave or break countdown from `WaveSpawner.timeline()` (top centre), gold (top right), "Lv n" and an XP bar from `draft.level_progress(run)` under the HP bar (D-153), one panel per skill slot with name, key hint, ready/seconds and a cooldown bar from `skills.ready_at` (bottom right); hidden while `world.run == null`. **Run flow (D-125, D-154):** `main.tscn` stays the main scene; CanvasLayer overlays after `PlayerInput` and `Hud`: `view/ui/start_screen.tscn` (`StartScreen`: Play opens the hub), `hub.tscn` (`Hub`: loads the profile on open; hearts, one "Rescue {name}" button per `MetaProfile.offer` waifu with her `best_sec`, the 12 meta nodes in one column per branch with their `check_buy` state, the roster from `roster_state`, Back; a buy that `MetaProfile.buy` accepts saves the profile at once; an unreadable profile shows the D-161 notice first; buttons rebuilt only on open and after a buy; a rescue calls `RunFlow.start_rescue`, which queues `profile.start_command(..., "run_m3", waifu)` with a seed from a view-local `RandomNumberGenerator.randomize()`, printed to the log), `pause_menu.tscn` (`PauseMenu`, shown while RUNNING and paused; Resume and `ui_cancel` call `PlayerInput.set_paused(false)` and mark the event handled; Restart and Abandon run open a confirm "You keep {n} hearts" with `n = hearts_for(run, false, clock)` and Cancel focused (D-155); confirming records the run as a loss with `ProfileStore.record_run_end`, then reloads to the hub, or for Restart rescues the same waifu again) and `end_screen.tscn` (`EndScreen`, shown on WON/LOST with the time survived from `world.clock`; it records the run end once on the first refresh that sees WON or LOST and shows "+{n} hearts" and, on a win, the waifu who joins; Continue -> hub), plus `draft_overlay.tscn` (`DraftOverlay`, D-153, shown while `PlayerInput.in_draft`: RUNNING, not paused, `draft.drafting`; 3 card buttons from `world.draft.draft` with `tr(name_key)`, `draft.type.<type>` and `tr(desc_key)`; a pick queues `PICK_CARD(slot)` once and disables the buttons until the picks total changes, i.e. the next draft; first card focused on open and after a pause). `PlayerInput.handle` passes only `pause` while `in_draft` and `_process` does not pan. Leaving a run is `reload_current_scene()`: a fresh `SimWorld` and fresh views, no reset code. Flow state is static vars on `view/run_flow.gd` (`RunFlow.screen` START or HUB, `restart_waifu` for Restart, `save_dir` for the profile and settings folder, default `user://`, `slow_time_placing`); they survive the reload. `slow_time_placing` is also saved in `settings.json` (`save/settings_store.gd`, D-157): loaded in `game_view._ready` on every scene load (missing, unreadable, newer or mistyped = off), written by each toggle. **Slow time while placing** scales only the delta fed to `SimDriver.advance` (`RunFlow.time_scale`, `slow_time_scale` in `data/ui`), never `Engine.time_scale`: every tick is still one `SIM_DT` step with the same commands stamped with `world.tick`, so the run stays deterministic (`test_run_flow.gd`). With `demo == false` (bench) the overlays stay hidden. Text is rebuilt only when the value behind it changes; every HUD control has `mouse_filter = IGNORE` except the build bar buttons. **Build UI (D-122):** `setup(world, input, ghost)`; `view/ui/build_bar.gd` (`BuildBar`, bottom centre) has one button per buildable tower in `world.tower_types` (4-column `GridContainer`, rebuilt when the run or the list size changes; name, `price`, hotkey `[1]..[8]`; click = `PlayerInput.select_tower`, greyed when gold is short, disabled unless `PlayerInput.can_build`); `view/ui/radial_menu.gd` (`RadialMenu`) draws the gamepad radial while `PlayerInput.menu_open` and selects on `build_menu_closed`; `view/placement_ghost.gd` (`PlacementGhost`, a Node3D in `main.tscn` before the HUD) calls `check_place` once per frame, draws the footprint box and range ring in the valid/invalid colour, and builds the cursor hints (`hint()`: reason or price, sell with `sell_refund`, rebuild with `rebuild_price`, upgrade price or refusal with `TowerUpgrade.check` on towers with `max_level > 1`, D-151) that the HUD `Cursor` label shows at the cursor's screen projection. `view/ui/tower_levels.gd` (`TowerLevels`, a Control in the HUD before `Cursor`) keeps a Label pool with "Lv n" above every tower (live or husk) with `max_level > 1`, at the unprojected tower position raised by `level_label_height`; text rebuilt only on a level change (D-151). Ghost, radial and label tunables in `data/ui/*.json` (schema `tools/schemas/ui.schema.json`), placeholders. **The view never re-implements a rule:** every verdict or price the UI shows comes from a read-only sim query that the command path itself uses (`TowerBuilding.check_place`, `price`, `rebuild_price`, `sell_refund`, `TowerUpgrade.check`, `WaveSpawner.timeline`). **Theme and readability (D-039):** one project theme `view/ui/ui_theme.tres` (`gui/theme/custom`), default font size 36, Label outline; no font below 32 px at base (16 px on the Deck at the 0.5 `canvas_items` scale); HUD margins 48 px. **Localisation (D-063):** Godot translations from `game/loc/strings.csv` (`keys,en`; a new language is a new column), imported by Godot (`strings.csv.import` committed, `*.translation` gitignored; `test.ps1`, `run.ps1` and `export.ps1` import first) and listed in `[internationalization] locale/translations`. The validator checks that every `*_key` value in `game/data` is a key of the CSV.
- **Input layer [P] (D-119):** `input/player_input.gd` (`PlayerInput`, a node in `main.tscn`) is the only code that reads devices (`Input`, `InputEvent`). It gives the view intents (camera calls, `selected_tower`, `cursor`, `menu_open`, `build_menu_closed`) and the sim `SimCommand`s through `world.queue()`; it never changes sim state directly. Default bindings live in the InputMap in `project.godot`; a headless test checks every action has a keyboard/mouse and a gamepad binding (except the listed device-specific ones). Mapping: `09_CONTROLS.md`.
- **Fallback decision:** if 3D billboarding costs too much on Steam Deck, switch the view layer to pure 2D with iso-looking art. Because the simulation is independent of rendering (below), this is a contained change.

## 3. Architecture: simulation / view split **[D]**
> Confirmed by the owner on 2026-10-08 (D-020, D-037).

```
game/
  sim/      <- pure game rules. No Node/scene dependencies. Deterministic with a seed.
  view/     <- rendering, VFX, audio, UI. Reads sim state; never mutates rules.
  data/     <- content: waifus, enemies, outfits, cards, waves (JSON or .tres)
  input/    <- keyboard/mouse/gamepad mapping to sim commands
  save/     <- profile (and later suspend) files: file I/O only, no Node, no rules (D-152)
  tests/    <- headless tests
```
- The sim exposes a fixed-timestep `step()` (each call advances exactly one `SIM_DT` tick; the caller accumulates frame time, D-069) and a command queue (`PlaceTower`, `UseSkill`, `PickCard`...).
- The sim stores entities in **packed arrays** (structure-of-arrays: positions, hp, types) for speed.
- Spatial queries (nearest enemy, collisions) through a **uniform spatial hash grid**.
- Why: (1) performance, (2) **headless balance simulation** (run thousands of runs overnight), (3) swappable view layer, (4) agents can test rules without launching the game.

### 3a. Concrete sim contract **[P]** (details for implementers; the 30 Hz tick is decided, D-038)
- **Tick:** fixed `SIM_DT = 1/30 s`; the view interpolates positions between the previous and current tick. Render rate is independent.
- **View driver (D-086):** `view/sim_driver.gd` (RefCounted) accumulates frame time and runs one `step()` per `SIM_DT`, at most 5 per frame; time beyond that is dropped (no spiral of death). `step()` itself copies `pos_x`/`pos_z` into `enemies.prev_x`/`prev_z` at its start (D-120), and `add()` sets them to the spawn position; rendering uses `lerp(prev, current, alpha)` with `alpha = accumulator / SIM_DT`. Since `prev_*` go through `remove()` like every enemy array, slot `i` always interpolates from its own enemy (the M1 swap-remove gap is fixed). A recycle can still jump far in one tick: the horde view snaps to the current position when the jump is above 2 units (`HordeBatcher.SNAP_DIST_SQ`, D-087). `on_step` (a Callable) is called after each `step()`, so the view reads every step's events before they are cleared.
- **Units:** 1 world unit = 1 metre-ish; Guardian at (0, 0); ground plane x/z; the sim never uses floats from the view or from `delta`.
- **Determinism:** one `RandomNumberGenerator` per concern (spawns, loot, cards, combat), each seeded from the run seed as `hash([run_seed, "<concern>"])` (e.g. `_spawn_rng` uses `"spawns"`); no use of global `randf()`; iteration order over entity arrays is by index; no dictionaries iterated in unordered fashion for results.
- **Commands (only way to change the sim from outside, D-100):** `SimCommand` (`sim/sim_command.gd`) with `type` in `START_RUN{run_seed, run_id, guardian_id, unlocked, meta_nodes}` (`run_id` = a `data/runs` id; `guardian_id` = a `data/guardians` id, empty = the run file's `guardian`, D-146; `unlocked` = rescued waifu ids for card eligibility, empty = nothing rescued, D-147; `meta_nodes` = bought meta-tree ids, D-152), `PAUSE{paused}`, `PLACE_TOWER{tower_id, x, z}` (`tower_id` = a `data/towers` id), `SELL_TOWER{tower_uid}`, `REBUILD_TOWER{tower_uid}`, `UPGRADE_TOWER{tower_uid}` (D-144), `USE_SKILL{skill_id}` (a `data/skills` id), `PICK_CARD{slot}` (0-2, D-147); one static constructor per type. `tower_uid` is a stable id assigned on placement (`world.next_tower_uid`, from 0, never reused), never an array index (D-081). Every command carries `tick`: `SimWorld.queue(cmd)` stamps `tick = max(cmd.tick, world.tick)` (a late command applies at the next step; the stamped tick is what a replay records) and keeps the queue sorted by tick, then enqueue order. `step()` applies every queued command with `tick <= world.tick` first, so a run replays from `(seed, commands)`. StartRun is ignored unless IDLE; it reseeds the RNGs (`_seed_rngs`) and loads `RunData`; after `gold = starting_gold` and the modifier store reset, and before the build grid is sized, every `MetaCatalog` node in id order that is in `meta_nodes` applies its effects through `CardEffects.apply` (`gold` adds to the starting gold, the rest goes to the store; D-152 rule 8). PlaceTower, SellTower, RebuildTower and UpgradeTower apply only while RUNNING, not paused (D-105) and not drafting (D-147); a rejected building command changes nothing and pushes no event. Handlers in `sim/tower_building.gd` (D-109): **PlaceTower** is `check_place(w, tower_id, x, z)` then commit; `check_place` is the single placement rule (D-121), read-only, and returns a `Check` (`reason` in check order `OK, NOT_OFFERED, OCCUPIED, OUT_OF_RADIUS, TOO_CLOSE, NO_GOLD`, snapped centre `x, z`, `footprint`, `price`), so the build UI shows exactly what the command will do. It snaps to the build grid and is rejected unless `tower_id` is in the buildable list `world.tower_types` (D-147), the footprint is inside the grid and every cell is free (a husk's cells are taken), the snapped centre is inside the current build radius (`dist + radius <= world.build_radius`, D-148) and off the Guardian (`dist >= guardian_contact_radius + radius`), and `gold >= price` with `price = floori((cost + cost_per_copy * copies) * (1 + price mult))` (copies = towers of that type, husks included, D-113; the `price` mult is meta only, D-152); it appends the tower with full HP and `paid = price`. Enemies standing on the footprint do not block it (D-112; the flow field pushes them out, see Pathing). **SellTower** refunds `floori(paid * clampf(sell_refund + sell_refund adds, 0, 1))` (meta adds, D-152) for a live tower, 0 for a husk (D-113), frees the cells and swap-removes the tower (uids stay stable). **RebuildTower** applies only to a husk, costs `maxi(0, floori(paid * maxf(0, rebuild_fraction + rebuild_fraction adds) * (1 + rebuild_mult)))` (D-113, D-148, D-152; the three prices add `1e-4` before rounding down to absorb float32 sums; `TowerBuilding.rebuild_price`, shared by the UI and the command) and restores full HP (`max_hp`) and solid cells; `paid` and the level are unchanged. **UpgradeTower** (`sim/tower_upgrade.gd`, D-144) is `TowerUpgrade.check(w, uid)` then commit, like PlaceTower: `check` is read-only and returns `reason` (check order `OK, NO_TOWER, HUSK, MAX_LEVEL, LOCKED, NO_GOLD`), `price` (the next level's `cost`, never grows with copies) and `level`; commit: `gold -= price`, `paid += price` (so sell and rebuild follow, D-113), `level += 1`, `TOWER_UPGRADED`. LOCKED = the next level has `needs_card` and the modifier store holds no `unlock_level` entry of at least that level for this tower. **UseSkill** (D-110) applies only while RUNNING, not paused and not drafting; slot = `run.skill_ids.find(skill_id)`; an unknown id or a skill on cooldown is ignored (no event). See Guardian skills.
- **Events out (for the view, D-100):** `world.events` (`SimEvents`, `sim/sim_events.gd`) holds the events of the last `step()` as SoA: `kind, a` (`PackedInt32Array`), `x, z, value` (`PackedFloat32Array`), `count` valid entries. Cleared at the start of every `step()` (capacity kept; it grows by doubling and never allocates once its peak is reached). The driver runs up to 5 steps per frame, so the view reads events after **each** step. Events never hold enemy indices (D-081). The view reads events and state arrays; it never calls back into rules. Payload per kind (the emitting tasks fill them):

  | Kind | a | x, z | value |
  |---|---|---|---|
  | ENEMY_DIED | enemy type_id | position | gold gained (base + mark, D-145) |
  | ENEMY_HIT | enemy type_id | position | damage |
  | TOWER_PLACED | tower_uid | position | tower type (also pushed on rebuild, same uid) |
  | TOWER_DIED | tower_uid | position | 0 |
  | TOWER_SOLD | tower_uid | position | gold refunded |
  | TOWER_FIRED | tower_uid | target position | tower type |
  | TOWER_UPGRADED | tower_uid | tower position | new level (D-144) |
  | TOWER_HIT | tower_uid | attacker position | damage (walled-in enemy, D-116) |
  | SKILL_USED | skill slot | 0, 0 | 0 |
  | GUARDIAN_HIT | source enemy type_id | source position | damage after shield |
  | WAVE_STARTED | wave index (0-based) | 0, 0 | 0 |
  | RUN_ENDED | 1 won, 0 lost | 0, 0 | 0 |
  | LEVEL_UP | new level | 0, 0 | 0 (D-147) |
  | CARD_PICKED | card index (`CardCatalog`) | 0, 0 | slot (D-147) |
  | TOWER_REPAIRED | healed tower_uid, -1 = the Guardian | repairer position (D-163) | HP restored (D-150) |
- **Run state (D-100):** `SimWorld.run_state` in `IDLE, RUNNING, WON, LOST` (the DEATHS phase sets WON, the Guardian hit that takes her to 0 HP sets LOST; see Combat), plus `paused`. `tick` is the command clock and advances on every `step()`; `clock` is the run clock (013's timeline reads it) and advances only while RUNNING and not paused. While paused, drafting (`draft.drafting`, D-147), WON or LOST, `step()` applies commands and advances `tick` only: nothing moves. IDLE (no StartRun) still simulates, so the M1 demo, the bench and the tests behave as before. `state_hash()` includes `tick, clock, run_state, paused` and the run id, and `draft.hash_parts()` (XP, level, `xp_next`, pending, drafting, the open draft, picks, `cards` RNG state), `tower_types` and `unlocked` (D-147).
- **XP and card draft (D-147, `sim/card_catalog.gd`, `sim/card_draft.gd`, `sim/card_effects.gd`):** `CardCatalog` (cards sorted by id; waifu refs resolved to tower types through `data/waifus`). In DEATHS every removed enemy adds `xp[type] * xp_mult` to the float `draft.xp`; at the end of DEATHS (RUNNING only) each crossed threshold pushes `LEVEL_UP` (level += 1, `xp_next += xp_base + xp_step * (level - 1)`, pending += 1), then if no draft is open and pending > 0 one opens: 3 slots, each draws a type among `new_tower, signature, skill, perk` (that order) that still has an undrawn eligible card by `card_type_weights` (one `randf`), then a card uniformly within it in id order (one `randi_range`), with the `cards` RNG; an empty slot gets the filler (`card_purse`). Eligible: not filler, `picks < max_picks`, `requires.unlocked` in StartRun `unlocked`, `requires.buildable` waifu's tower in `world.tower_types`, and a `new_tower` card's tower not yet buildable. The rest of the tick still runs; the next ticks are frozen (above). `PICK_CARD{slot}` (RUNNING, drafting, not paused, slot 0-2) applies the card's effects in order, `picks += 1`, `CARD_PICKED`, closes the draft, pending -= 1 and opens the next at once if pending > 0. Effects: `gold` = instant gold; `unlock_tower` appends that tower to `world.tower_types` (a copy of `run.tower_types` at StartRun; the build bar, radial and slot keys read it, D-153); everything else goes to the modifier store unfiltered (D-144). `xp_mult` and `kill_gold_mult` = `(1 + add) * (1 + mult)` of the `run`-targeted entries, cached with the tower recompute; a kill's base gold (when rolled) is `floori(gold * kill_gold_mult)`, then mark (D-145) and bounty (D-146) gold are added flat. Run-scope effects (D-148), cached with the same recompute: `world.build_radius` = `run.build_radius` + `build_radius` add on `run` (hashed); `rebuild_mult` = `rebuild_price` mult on `run`; `detour_mult` = `detour_damage` mult on `all_towers` (see Build area, RebuildTower, Tower attacks). The bench takes slot 0, the balance bot the best-ranked card (D-164); the game view picks through the draft overlay (D-153). Read-only for the view: `CardCatalog.name_key` / `desc_key`, `draft.level_progress(run)` (XP bar fill between the current level's threshold and `xp_next`, 0-1).
- **Entity arrays (SoA, `PackedFloat32Array` / `PackedInt32Array`):** enemy `pos_x, pos_z, hp, type_id, state, anim_frame, cooldown, slow_factor, slow_ticks, target_id` (tower uid the enemy attacks, -1 = the Guardian; D-116), `mark_gold, mark_until` (mark, D-145; `mark_until` = absolute run clock tick); tower `pos_x, pos_z, attack_range, target, uid, type_id, paid, cell_i, cell_j, footprint, hp, husk, cooldown, level` and the derived stats `attack_range, damage, reload` (cooldown ticks after a shot), `max_hp, splash_radius, slow_factor, slow_ticks` (hashed, D-144), `thorns, mark_gold, mark_ticks` (hashed, D-145), `reach, heal, guardian_heal, heal_targets, syn_mask` (hashed, D-150) with the flag `stats_dirty`, plus the derived `uid_index` (tower index by uid, -1 = none, refreshed in the PATH phase, not hashed) (`waifu_id` is added when used).

- **Tower attacks (implemented in `sim/tower_attacks.gd`, D-114):** in the ATTACKS phase, only while RUNNING, towers fire first, in index order, then the enemies attack, so an enemy killed by a tower this tick does not attack. Bare towers (`type_id < 0`) and husks never fire. Per-tower `cooldown` in ticks (0 at placement and at rebuild): each built live tower decrements it if > 0; then if it is 0 and its `target` is alive (`hp > 0`) it fires and resets it to its derived `reload`: the first shot as soon as a target is in range, then one every `cooldown` ticks. A target killed earlier in the same phase is not shot: the tower holds (cooldown stays 0) and fires next tick at its new nearest target (no in-phase retarget). A shot is instant (D-098): `TOWER_FIRED`, then by the type's `attack`, with the tower's derived `damage`, `splash_radius`, `slow_factor`, `slow_ticks` (D-144): `single` -> `damage_enemy(target, damage)`; `splash` -> every enemy whose centre is within `splash_radius` of the target's centre (target included, no falloff, `grid.query_radius`, ascending index) takes `damage` through `damage_enemy` (corpses ignored); `slow` -> `damage_enemy(target, damage)`, then the slow on the target (bosses too, placeholder); `slow_area` (D-145) -> the `splash` query, every enemy hit takes `damage_enemy` then the slow, in query order; `mark` (D-145) -> `damage_enemy(target, damage)`, then `TowerAttacks.mark`: a mark is active while `clock < mark_until`, an expired one counts as none; `mark_gold = max(active gold, tower mark_gold)`, `mark_until = max(active until, clock + mark_ticks)` (higher gold wins, longer expiry wins, no stacking). `wall`, `aura`, `repair` never target, so never fire. **Repair (D-150)**: a `repair` tower counts its cooldown down the same way and, at 0, pulses and resets it to `reload` (Crescendo does not apply), before any target check: the `heal_targets` live towers of her list with the lowest `hp / max_hp` below 1 (ties: lower uid) each get `heal`, capped at `max_hp`; if none needed it and the Guardian's body is within `reach` (`d - guardian_contact_radius <= reach`) and below `guardian_max_hp`, she gets `guardian_heal`, capped; a pulse with nothing to heal is spent. `TOWER_REPAIRED` per heal. **Detour damage (D-148):** every tower hit goes through `TowerAttacks._hit`; when `detour_mult != 0` and the flow field exists, an enemy whose cell has `field.hit[c] != -1` (its straight line to the Guardian is blocked: it is detouring; outside the grid counts as clear) takes `damage * (1 + detour_mult)`; no lookup when it is 0. Skills and thorns are not tower shots: unchanged. **Slow (D-117)**: enemy `slow_factor` (1 = none) and `slow_ticks` (0 = none); a hit `(f, n)` sets `slow_factor = f` if `slow_ticks == 0` or `f < slow_factor`, and `slow_ticks = max(slow_ticks, n)`: no stacking, the strongest applies, a hit refreshes to the longer duration (`TowerAttacks.apply_slow`). A hit in tick T slows exactly the MOVE phases of ticks T+1..T+n (see Enemy movement).

- **Demo recycle (test/benchmark/demo API, D-087):** `SimWorld.recycle_radius` (default 0 = off). When > 0, in the MOVE phase right after the movement, every stopped enemy (`ATTACKING` or `QUEUED`) is moved, in index order, to a point on the ring of that radius (angle from `_spawn_rng`) and set back to `MOVING`; no removal, so indices and count are unchanged. - **Enemy movement (implemented in `sim/enemy_movement.gd`, D-107):** two passes in the MOVE phase. **Steer** (each live enemy): `d` = distance to the Guardian at (0, 0), direction `-pos / d` (0 if `d < 1e-6`), `gap = d - stop`, with `stop = guardian contact_radius + radius + attack_range` per type (range between body edges; `attack_range` 0 = melee = contact). Before StartRun (IDLE) the contact radius is 0, so the M1 demo and bench stop at their own radius. **Advance**: `gap <= 0` -> `ATTACKING`, no move; else if `blocked` -> `QUEUED`, no move; else if `gap <= speed * SIM_DT` -> move by `gap`, `ATTACKING` in the same tick; else move `speed * SIM_DT`, `MOVING`; `speed` is multiplied by `slow_factor` while `slow_ticks > 0` (D-114). At the end of each live enemy's advance (moving or not) `slow_ticks` counts down by 1, and `slow_factor` returns to 1 when it reaches 0. States (`SimEnemies.State`): `MOVING = 0, ATTACKING = 1, QUEUED = 2` (QUEUED = stopped behind the crowd, does not attack). The state is re-evaluated every tick: an attacker pushed out by separation walks back in, a queued enemy walks on once pushed clear. **Queue flag**: the separation pass sets `EnemySeparation.blocked[i]` (zeroed each tick) when `i` overlaps an enemy that is stopped (`state != MOVING`, last tick's state) and closer to the Guardian (smaller queue key: `x*x + z*z` without a flow field, else the path cost, see Pathing); chains form a queue, which keeps a piled crowd soft (D-079) and cheap, and with towers enemies queue along corridors. Corpses (`hp <= 0`) are skipped. With a flow field, `steer()` routes around towers and `push_out()` runs after `advance()` (see Pathing, D-115).
- **Pathing (implemented in `sim/flow_field.gd`, `sim/flow_geometry.gd`, D-115):** maze pathing over the build grid, every enemy a point (D-111). **Field**: `SimWorld.field` (`FlowField`, same cells and indexing as `BuildGrid`) is created, and computed in full at once, in the PATH phase whenever `world.build` exists and the field was made for another grid (StartRun, or a test/bench setting `world.build` on an IDLE world; contact radius 0 when IDLE). Goal cells: free cells whose centre is within `max(guardian_contact_radius, step)` of (0, 0). Per cell, integer and deterministic: `dist` = octile cost to the goal (2 per orthogonal, 3 per diagonal step; Dial's algorithm, 4 cyclic buckets, lazy deletion, 8 neighbours in the fixed order E, W, S, N, SE, SW, NE, NW with E = +x and S = +z; a diagonal step only if both orthogonal neighbours are free, so towers touching at a corner form a wall; solid and unreachable cells `INF = 1 << 30`); `dir` = index 0..7 of the step toward the goal (`FlowField.DIR_X`, `DIR_Z` unit vectors; 255 = none); `hit` = first solid cell on the straight line from the cell centre to the Guardian (-1 = clear), from static geometry (`FlowGeometry`: cells sorted by the integer key `(2i - S + 1)^2 + (2j - S + 1)^2` then index, `pred` = the cell holding `centre - step * centre / |centre|`, -1 for goal-radius cells): `hit[c] = c` if solid, -1 if no pred, the first solid orthogonal cell (x first) when the step to pred is diagonal, else `hit[pred]`; `escape` = nearest free cell (itself when free), 4-neighbour BFS from the free cells bordering solid ones, seeded in index order. **Recompute only on change, with a work budget**: when no computation runs and `build.version` differs from the last one computed, a computation starts on a copy of `build.solid`; each tick it does at most `FlowField.CELLS_PER_TICK` = 4000 units (one cell reset, settled cell, hit cell or escape cell) into working arrays, swapped into the published ones when it ends. A change during a computation is picked up when it ends (no restart), so the per-tick cost is bounded whatever the change rate. A full computation is about 25k units: 7 ticks (0.23 s) at 4000, so a layout change shows up within at most two computation lengths. Not in `state_hash()` (derived from the tower arrays and the command history). **Steer** (per live enemy, `c` its cell): no field or outside the grid: straight to the Guardian (as before; outside, that is toward the build area); inside a tower: `c = escape[c]`; `hit[c] == -1`: straight, with the D-107 `gap` (so the open field and every cell with a clear line move exactly as without towers); else `gap = BLOCKED_GAP` (1e9: the enemy keeps walking and never attacks the Guardian through a tower, D-118, ranged enemies included) and the direction is `dir[c]`, **Walled in** (`dist[c] == INF`, D-116): with `h = hit[c]` and `t = uid_index[owner[h]]`, the enemy heads for that tower's centre with `gap = |p - tower| - (tower radius + radius + attack_range)` (D-107 body-edge rule, ranged enemies too) and `target_id = owner[h]`; if the cell's tower is sold, missing or a husk (the field lags a few ticks) it keeps the straight chase with `BLOCKED_GAP` and `target_id = -1`. Every other case sets `target_id = -1`. A husk (D-104) or a sale frees the cells and bumps `version`; within the field latency those enemies get a path and walk through the gap. **Push-out (D-112)**: after `advance()`, before the recycle, each live enemy whose cell is solid in `build.solid` and has `escape[c] != c` is clamped into the square of `escape[c]` (`1e-4` inside); an enemy inside a tower placed less than one computation ago is pushed out once the field catches up. **Queue key** (`EnemySeparation`, filled once per tick before the pair loop): no field: `x*x + z*z` (the D-107 compare, unchanged); outside the grid or clear line: `d * 2 / step` (straight distance in cost units); `dist[c] == INF`: `1e6 + d` (behind every enemy with a path); else `dist[c] + 1e-3 * d` (the radial term only breaks ties inside a cell). Test/bench API: `TowerBuilding.add_built(w, type, x, z)` snaps, appends and fills a built tower with no gate, gold or radius check.
- **Combat (implemented in `sim/sim_world.gd`, D-107):** `damage_enemy(i, amount)` is the single entry point for every damage source (towers, skills): ignored on a corpse (`hp <= 0`), else `hp -= amount` and an `ENEMY_HIT` event. A killed enemy stays in the arrays, inert (no move, no attack), until the DEATHS phase of the next tick, which scans from the highest index down, swap-removes every `hp <= 0` enemy, rolls its gold (`gold_chance >= 1` or `_loot_rng.randf() < gold_chance`; `_loot_rng` is seeded from `hash([seed, "loot"])`), adds it to `gold` at once (D-094) and adds the enemy's `mark_gold` if `clock < mark_until` (independent of the roll, after the base gold; D-145) adds `bounty_gold` while `clock < bounty_until` (Clearance Sale, flat, D-146) and pushes `ENEMY_DIED` (value = gold gained, mark and bounty included). Removing there keeps one grid rebuild per tick (D-083); the view hides `hp <= 0` enemies (D-120); `damage_enemy` also stores `hit_tick` for the view's hit flash. Enemy attacks (ATTACKS phase, only while RUNNING): per-enemy `cooldown` in ticks (0 at spawn); each live enemy decrements it if > 0, then if it is 0 and the enemy is `ATTACKING` it hits its target for `damage`: with `target_id >= 0` (walled in, D-116) the tower `uid_index[target_id]`, if it exists and is not a husk, gets `TOWER_HIT` (a = uid, attacker position, damage) then `damage_tower` (a lethal hit leaves a husk, D-109), then, if the tower's derived `thorns > 0`, `damage_enemy(attacker, thorns)` (a normal `ENEMY_HIT`; every landed hit, the lethal one too; D-145), otherwise there is no hit and the cooldown stays 0; with `target_id == -1` the Guardian (instant, D-098, melee and ranged alike) and resets it to `attack_cooldown`: the first hit lands on arrival, then one every `attack_cooldown` ticks. While `clock < guard_until` (Stand Firm, D-146) `damage_tower` and `_hit_guardian` multiply the damage by the signature `damage_factor` (the `TOWER_HIT` value is the reduced damage). Hits go through `_hit_guardian()`, the only path for damage to the Guardian: Stand Firm, then the Shield absorbs (Guardian skills), then `guardian_hp -= dmg`, `GUARDIAN_HIT` (value = damage after the Shield, even 0). `gold` comes from the run at StartRun; `guardian_hp = guardian_max_hp` (D-146: Guardian `hp` with the `guardian`-targeted `hp` modifiers, recomputed with the tower stats when `stats_dirty`, a rise adds the difference, a fall clamps; hashed). **Lose**: `guardian_hp <= 0` -> `LOST`, `RUN_ENDED` (a = 0), the attack loop stops. **Win**: when DEATHS removes the run's `final_boss_type` -> `WON`, `RUN_ENDED` (a = 1) after its `ENEMY_DIED` (mini-bosses never win). If the Guardian dies in the tick the boss's lethal hit lands, the run is LOST (the frozen world never reaches the next DEATHS).
- **Guardian skills (implemented in `sim/guardian_skills.gd` (state), `sim/signature_skills.gd` (casts) and `SimWorld._use_skill`, D-110, D-146):** the Guardian comes from StartRun's `guardian_id`; her signature slot (`run.signature_slot`) is her first skill whose kind is not `shield`. Cooldowns on the run clock: per slot `skills.ready_at` (0 at StartRun, so both skills are ready at the start), usable when `clock >= ready_at[slot]`, on use `ready_at = clock + cooldown`, with cooldown = `TowerStats.clamped_ticks(skill_cooldown, skill_cooldown sums)` (add in seconds, clamped at 50% and 1 tick); skill modifiers target `guardian` (all her skills), `signature` (the signature slot) or `skill:<id>` (`SimModifiers.skill_sums`), read once per cast; the run clock stops while paused, so the cooldown does too; nothing is decremented per tick (the UI reads `ready_at` and `clock`). An accepted use pushes `SKILL_USED` (a = slot) first. Signature power `p` = sum of `skill_power` mult (signature slot only) multiplies the fields in the skill's `power_stats` (x (1 + p); `gold_per_kill` rounded down; durations converted to ticks after the multiply). Casts run in the COMMANDS phase, on the tick's starting positions; timed effects store an absolute run-clock `until` (frozen while paused). **Area blast** (Big Finish): every enemy whose body touches the disk of `skill_radius` around the Guardian (`sqrt(x*x + z*z) - radius[type] <= skill_radius`) takes `skill_damage` through `damage_enemy`, linear scan in index order (corpses ignored); the kills are removed in the same tick's DEATHS phase. **Snare** (Tangle): same scan, `apply_slow(skill_slow_factor, duration)` (D-117, bosses too). **Guard** (Stand Firm): `guard_until = clock + duration` (see Combat). **Bounty** (Clearance Sale): `bounty_until`, `bounty_gold` (see Combat). **Haste** (Crescendo): `haste_until`; while `clock < haste_until`, `TowerAttacks.fire` resets a tower's cooldown to `max(1, roundi(reload * cooldown_factor))`. **Rebuild** (Emergency Rebuild): every husk is restored free (`TowerBuilding.restore`, as RebuildTower: full HP, cells solid, `TOWER_PLACED`, level kept), then the Guardian heals `guardian_heal` (capped at `guardian_max_hp`). **Shield**: on use `shield_left = skill_absorb * (1 + shield_absorb mult)`, `shield_until = clock + ticks(duration_sec + shield_duration add)` (a recast replaces, never stacks), then heals `shield_heal` add (Mending, capped); while `clock < shield_until`, `_hit_guardian` absorbs `min(dmg, shield_left)`. `ready_at`, `shield_left`, `shield_until`, `guard_until`, `bounty_until`, `bounty_gold`, `haste_until` and `guardian_max_hp` are in `state_hash()`.
- **Spatial hash (implemented in `sim/spatial_grid.gd`, D-082):** a bounded uniform grid over the square `[-64, 64]` on x/z; positions outside are clamped into the edge cells, so queries stay exact anywhere (only slower far out). Cell size = largest horde collision diameter = `2 * max(radius)` over the horde (non-boss) types of the enemy catalog, derived from data (currently 0.8 units, brute radius 0.4; D-108, was `4 * max(radius)` until task 025), so the separation scan reach `r_i + max_radius` spans at most one cell beyond the enemy's own. Bosses are excluded so one large radius does not grow every cell (D-099); bosses get their own separation pass (D-106, below). `SimWorld.step()` rebuilds it after enemy movement each tick with a counting sort into packed arrays (no per-cell arrays, no allocation once the enemy count has peaked); it is derived state, not in `state_hash()`. Queries take the position arrays as arguments: `query_radius(x, z, r, xs, zs, out)` fills `out` with the indices within `r`, ascending; `nearest(x, z, max_range, xs, zs)` returns the closest index within `max_range` (lowest index on ties) or -1; it searches square rings of cells outward, scans each ring's top and bottom rows as one contiguous `cell_items` range and its side cells one by one, and stops once a ring cannot beat the best distance (the result does not depend on the visit order).
- **Enemy separation (implemented in `sim/enemy_separation.gd`, D-079, D-084):** two enemies overlap when their distance `d < r_i + r_j` (the collision `radius` from data is the separation radius). Each one is pushed directly away from the other by `0.5 * overlap * separation_strength` of its own type (`overlap = r_i + r_j - d`; `separation_strength` in enemy data, 0..1), so strength 1 resolves a lone pair in one tick and strength 0.5 halves the overlap per tick; the chase keeps a small overlap in a dense crowd. Jacobi style: all pushes are computed from the positions at the start of the phase, then applied in one pass; each pair is visited once in fixed grid order, so the result is deterministic. **Visit order (D-123):** positions and radii are first copied into grid cell order (`cell_items` order, packed arrays kept between ticks); each horde enemy, in cell order, scans the cell box of reach `r_i + max_radius` but skips the rows below its own and starts its own row right after itself, so every overlapping pair is seen exactly once without an index test; the inner loop reads only the cell-ordered copies, and the enemy index, type, queue key and state only for an overlapping pair. Pushes accumulate by enemy index. On a queue-key tie the lower index is the one behind (as with `i < j`); floats are summed in cell order (deterministic, last-bit differences only). Coincident enemies (`d < 1e-6`) are pushed along x: `-x` for the lower index, `+x` for the higher. The total push of one enemy per tick is capped at its own radius. **Boss pass (D-106):** the horde loop skips every pair with a boss (`is_boss`), since its scan reach `r_i + max_radius` misses a boss's larger radius; bosses are collected in index order, then each boss scans the grid cells within `r_boss + max_radius` for horde enemies and checks every later boss directly (bosses are few), with the same pair rule and Jacobi buffers, before the capped apply pass. Every enemy is pushed whatever its `state`, and `state` is not changed; the pass also fills the queue flag `blocked` (see Enemy movement, D-107). It iterates the grid cells (`cell_start`/`cell_items`) directly instead of `query_radius`, because one query per enemy cost about 73 ms per tick at 3000 piled enemies; the grid lookups are inlined (task 025). Cost after task 025: about 25-38 ms per tick for 3000 enemies piled at the Guardian in headless debug (`test_separation_cost_3000_piled`), and in the release bench 3.4 ms (`pc_typical`, `pc_stress`) and 5.1 ms (`pc_piled`) per tick (it was 5.4-7.9 ms before task 025); task 014's queue rule makes the pile less dense: about 12.6 ms headless debug. After task 023 (D-123): about 9.3 ms headless debug; release 3.0 / 3.1 / 3.5 ms (`pc_typical` / `pc_stress` / `pc_piled`) and 4.8 ms in the maze (`pc_maze`, was 5.7 ms), see `reports/perf_m2.md`.
- **Waves and spawns (implemented in `sim/wave_spawner.gd`, D-106):** stateless, driven by the run `clock` (D-100) in integer ticks and `_spawn_rng`, so nothing new goes into `state_hash()`. With `P = wave_ticks + break_ticks`: nothing before `first_wave_tick`; then `rel = clock - first_wave_tick`, wave `w = rel / P`, offset `t = rel % P`. At `t == 0` a `WAVE_STARTED` event (a = w). `t < wave_ticks` spawns, `t >= wave_ticks` is the break and spawns no horde (D-032). Wave entry `e = min(w, waves - 1)`: the last entry repeats (D-096, D-099), `w` keeps counting. Even spread: at offset `t`, `((t + 1) * n) / wave_ticks - (t * n) / wave_ticks` enemies (`n = wave_count[e]`, integer division), exactly `n` per wave. Per spawn, RNG draws in this order: type by weighted pick over the entry's mix (`randf() * total weight`, cumulative walk), angle `randf() * TAU`, radius `lerp(spawn_ring_min, spawn_ring_max, randf())`, around the Guardian; hp from the catalog. Mini-bosses spawn when `clock == boss_ticks[k]` and the final boss when `clock == final_boss_tick`, after that tick's horde, on the same ring, in a wave or a break; the horde goes on after the final boss. Only while RUNNING: an IDLE world never spawns (M1 demo, benchmark and tests use `spawn_ring` and `recycle_radius`). The ring (30-44 in `run_m2`) is outside the camera pan bounds (`bounds_radius + bounds_margin` = 26); at the widest zoom near the pan edge the view can reach past it (CP-M2 playtest point). `WaveSpawner.timeline(clock, run) -> Vector3i(wave, in_break, ticks_left)` (D-121) gives the UI the same arithmetic read-only: `wave` 0-based (-1 before `first_wave_tick`), `in_break` 1 in a break and before the first wave, `ticks_left` until the next wave or break start.
- **Tick order (D-083):** `SimWorld.step()` runs these phases in this order: (0) commands (D-100): apply queued commands due this tick, then stop here if paused, drafting, won or lost; (0a) path (D-115): `FlowField.update` within its work budget, after creating the field when needed, then the tower `uid_index` refresh (D-116), then the Guardian max HP, the run multipliers (D-147) and `TowerStats.recompute` if `stats_dirty` (D-144); (1) enemy separation (task 004), which reads the grid built at the end of the previous tick, so grid and positions match exactly; (2) movement (steer, advance, push-out; D-107, D-115); (2a) deaths (D-107: removes the enemies killed since the last DEATHS, gold, XP, win, then level-ups and the draft, D-147); (2b) spawns (task 013, D-106: `WaveSpawner.step` while RUNNING); (3) grid rebuild, the only one per tick (about 2 ms per 3000 enemies in headless debug, task 003); (4) tower targeting (task 005) on the fresh grid, so every target is exact for this tick's positions; (5) attacks, only while RUNNING: tower attacks first (D-114), then enemy attacks (D-107; stops when the run is lost). Invariant: when `step()` starts, the grid matches the enemy arrays; as a safety net `step()` first rebuilds the grid if the enemy count differs from the last rebuild (enemies added or removed outside `step()`, e.g. `spawn_ring`). Phases that add, remove or move enemies (M2: deaths, spawns) go before (3). `step()` records the wall-clock time of each phase in `phase_usec` (indexed by `SimWorld.Phase`: `COMMANDS, PATH, SEPARATE, MOVE, DEATHS, SPAWN, GRID, TARGETING, ATTACKS`; the arrays are sized from `Phase.size()`) for the benchmark (task 008), and adds them to the running sum `phase_usec_sum` (the caller resets it; averages = sum / ticks run); both are diagnostics only, never read by rules and not in `state_hash()`.
- **Build area (D-042, D-109):** towers snap to a fine grid inside the build radius, which starts at about 20 units from the Guardian and can grow. `BuildGrid` (`sim/build_grid.gd`) is created once at StartRun from the largest reachable radius `max_build_radius` (D-148: `run.build_radius` + `build_radius` adds already in the store + for every card adding `build_radius`, `max_picks x value`, `CardCatalog.max_build_radius_bonus`) and `run.grid_step`, so a card pick never reallocates the grid or the flow field: a square of `S = 2 * ceili((max_build_radius + MARGIN) / step)` cells per side centred on the Guardian, `MARGIN = 2.0` units (112 x 112 for `run_m2`: 20 + `perk_expand` 2 x 3); placement needs `dist + radius <= world.build_radius` (the current radius: run radius + `build_radius` adds, updated in the stats recompute), so the margin is always free and enemies can walk around the outermost towers (D-115); cell `(i, j)` covers x in `[(i - S/2) * step, (i - S/2 + 1) * step)`, same for z with `j`, flat index `j * S + i`. Per cell `owner` (tower uid, -1 free; a husk keeps its cells) and `solid` (1 = live tower; husks are walkable, D-104); `version` is bumped on every change of `solid`, so pathing (FlowField) recomputes only then. A tower covers `n = max(1, ceili(2 * radius / step - 1e-4))` cells per side (radius 0.5, step 0.5: 2 x 2 cells); snap: first cell `i0 = roundi(x / step + S/2 - n/2)`, centre `(i0 + n/2 - S/2) * step`. The grid is derived from the tower arrays and not in `state_hash()` (the tower arrays and `next_tower_uid` are). Pathing treats every enemy as a point: any free cell is passable (D-111). Tower count is not capped, so tower arrays must grow dynamically and the M1 benchmark must include the 300-tower stress case.

- `data/runs/`: `run_m2` gains `xp_base`, `xp_step`, `hearts_win`, `hearts_loss_min`, `hearts_loss_max`, `hearts_min_sec` (D-165), `card_type_weights`. `run_m3` (D-147) is `run_m2` with the starter towers `tower_pip`, `tower_mallow`: the fixture for runs with waifu towers; `run_m2` stays the M2 fixture.

## 6. Testing **[P]**
- Unit/integration tests with a Godot test framework (**GUT**, D-033) run headless: `godot --headless ...`. The run fails if GUT ignores any test script (parse error, or not extending GutTest), via the post-run hook `tests/gut_post_run.gd`; a runtime error inside a test fails that test (GUT default).
- **Sim determinism test:** same seed + same commands = same result.
- **Text hygiene test (task 044):** `tools/tests/test_text_hygiene.py` scans every tracked text file (`git ls-files`; md, gd, json, ps1, py, cfg, tscn, gdshader, godot, csv, txt, tres, uid; `game/addons/gut/` skipped) and fails, naming `path:line:col`, on a control byte other than tab, LF and CR, on CRLF (the repo is LF), and in Markdown on a tab that is not at the start of a line. Why: agent-written Windows paths turn backslash sequences into control characters (`scripts` + backslash + `bench.ps1` became a backspace). Agents: in a shell or Python string, write a Windows path with forward slashes or `chr(92)`, never a bare backslash.
- **Balance runner (task 041, D-164; replaces the M2 runner of task 022, D-126):** `game/balance/` (not exported: `balance/*` is in the export `exclude_filter`). `BalanceBot` (`balance_bot.gd`) is a sim client like `PlayerInput`: it only queues `SimCommand`s and reads state and the read-only queries (`check_place`, `price`, `rebuild_price`, `TowerUpgrade.check`); no randomness; it acts every 15 ticks (0.5 s). While a draft is open it picks the slot whose card ranks first by `CardCatalog.Type` order (new tower, signature, skill, perk, filler; ties: lower card index). Otherwise it casts every ready skill and queues at most one build command: rebuild the first affordable husk; else the cheaper of the next placement and the cheapest upgrade whose `TowerUpgrade.check` is OK (ties: lower uid; placement wins a tie); no spot left: upgrade only; it waits for gold rather than change its plan. Strategies: `passive` (skills and cards only); `spread` (sunflower spiral around the Guardian, tower types round robin in buildable order, `wall` kinds skipped); `maze` (concentric rings `MAZE_RINGS` 2.5, 5.5, 8.5 (the inner ring hugs the Guardian so a few towers already close most of it), one `MAZE_GAP` 2 gap per ring alternating at angle 0 and PI, inner ring first, each ring built from the side opposite its gap toward the gap; angular slot k gets `pair[k % 2]`, the pair recomputed at each placement: the first buildable pair with a min-distance-0 relationship rule, preferring one with a `wall` kind, else the cheapest type). `balance_runner.gd` (`extends SceneTree`, run with `-s`) plays `run_m3` for strategies x profile presets (`fresh`: `MetaProfile.fresh`; `full`: every Guardian rescued and every meta node) x each Guardian of the preset's offer x seeds `1..N`, started with `MetaProfile.start_command` (the hub's path), through `SimWorld.step()` until WON, LOST or `MAX_SEC` 1000 (timeout = not won). Damage per source needs no sim change: each `ENEMY_HIT` value is credited to the latest `TOWER_FIRED` (tower kind), `TOWER_HIT` (thorns of the hit tower) or `SKILL_USED` (`skills`) of its step, overkill included. It writes `reports/balance_<date>.md`: the D-143 targets line and the maze vs spread summary line, per strategy x profile the win rate, death and win times, wins per Guardian, per run (Guardian, seed, outcome, end, towers bought, upgrades, husks rebuilt, skills used, gold earned, cards picked, relationships active at the end), per minute the median Guardian hp, gold earned, gold on hand, towers alive, linked towers, level and live enemies; damage per source; a Data section. `scripts\balance.ps1 -Runs N` (default 2, 54 runs; `-Profiles fresh,full`) runs it; the runner also takes `--only <strategies>`. `reports/balance_m2.md` stays as the M2 record.
- **Screenshot tests:** scripted scenes captured by a non-headless run for visual regression (human reviews diffs).
- **Perf benchmark scene (task 008, D-088):** `scripts\bench.ps1` exports the release build and starts it with the user arg `--bench` (release templates refuse a scene path argument), which opens `view/bench/bench.tscn`. Scenarios live in `data/bench/bench_m1.json` (seed, spawn rings, recycle radius, tower range, and per scenario enemies, towers, `piled`, warm-up, camera zoom, `render_scale`): `pc_typical` 3000/50, `pc_stress` 3000/300, `deck_typical` 1500/50, `deck_stress` 1500/150 (both at `render_scale` 0.5, about 1280x720 3D pixels, as the Deck pixel proxy) `pc_piled` 3000/300 and `deck_piled` 1500/150 (`render_scale` 0.5) with no recycle (the crowd piled at the Guardian); maze scenarios (task 024, D-115, `maze: true`): `pc_maze` 3000 and `deck_maze` 1500 (`render_scale` 0.5) lay out `maze_rings` (8, 13, 18) of built `maze_tower`s on a `BuildGrid` of `grid_step` (towers every 0.5 units of arc, one gap of `maze_gap` units per ring alternating at angle 0 and PI), and `pc_maze_churn` (3000, `churn: true`) flips one ring tower's cells every frame so a field recompute is always in flight (the worst case); the report adds `maze_towers`. Combat scenarios (task 023, `combat: true`): the harness starts `combat_run` (`run_m2`) with one step, then applies the `test_walled_in.gd` overrides (no wave spawns, no bosses, a Guardian that never falls), so the world is RUNNING and towers fire; `pc_combat` 3000/50, `pc_combat_stress` 3000/300, `deck_combat` 1500/50 and `deck_combat_stress` 1500/150 (`render_scale` 0.5) build real towers (`TowerBuilding.add_built`, the run's tower types in turn, at the sunflower positions; taken cells skipped), `pc_maze_combat` (3000) lays the maze on the run's build grid (same radius and step, tested; the grid itself is the larger reachable-radius one, D-148), and `pc_walled` (3000, `walled: true`, piled, no recycle) builds one full ring of `maze_tower`s at `walled_ring` (8; towers every 0.25 units of arc, tower hp set to 1e6 so the ring holds), the D-116 worst case.

### Data shapes (D-140)
Every new file: `schema_version` 1, `id` matching the file name, `placeholder: true`, text as keys only.

1. **`data/waifus/waifu_<id>.json`** (new schema `waifus.schema.json`): `name_key`, `role` (enum `damage, crowd_control, support, tank, economy`), `status` (enum `starter, guardian, rival`), `tags` (unique strings, from `07_ROSTER.md` 1), `tower` (tower id), and for `guardian` only (schema `if/then`, required): `guardian` (guardian id) and `offer_order` (integer 1..6). Files: pip, mallow (starters, no `guardian`), cinder 1, bastia 2, clover 3, hymn 4, tansy 5, poppy 6.
2. **`data/towers/tower_<waifu>.json`** (schema `towers.schema.json`, stays v1: only optional fields are added). `attack` enum gains `wall, aura, repair, mark, slow_area` (`tax` waits for Gilda). `range`, `damage`, `cooldown_sec` leave the top-level `required` and move into the per-kind `if/then`: `single`, `splash`, `slow`, `mark`, `slow_area` need all three; `repair` needs `range`, `cooldown_sec`, `heal`, `guardian_heal`; `wall` needs `thorns`; `aura` needs `aura_radius`, `aura_damage`, `aura_cooldown`; `mark` also `mark_sec`, `mark_gold`; `slow_area` also `splash_radius` (Tansy's "area", the same query as `splash`), `slow_factor`, `slow_sec`. New optional fields: `thorns` (damage), `aura_radius`, `aura_damage` and `aura_cooldown` (fractions: 0.2 = damage +20%, 0.1 = cooldown -10%), `heal`, `guardian_heal`, `heal_targets` (integer >= 1, default 1), `mark_sec`, `mark_gold` (integer). New optional `levels`: exactly 3 items (levels 2, 3, 4), each `{"cost": int, <changed stats>}` where the stats are any of `hp, range, damage, cooldown_sec, splash_radius, slow_factor, slow_sec, thorns, aura_radius, aura_damage, aura_cooldown, heal, guardian_heal, heal_targets, mark_sec, mark_gold` (no other key); the third item requires `needs_card` (a `card_sig_` id) and the first two must not have it (`prefixItems`). Values are absolute, not deltas (3.2). Files: `tower_pip`, `tower_mallow`, `tower_cinder`, `tower_bastia`, `tower_clover`, `tower_hymn`, `tower_tansy`, `tower_poppy`, values from the 3.2 table; shared `radius` 0.5, `sell_refund` 0.5, `rebuild_fraction` 0.3; `sprite` `towers/<waifu>`; `tags` `[]` (relationships live in the waifu file). The M2 files `tower_single_01`, `tower_splash_01`, `tower_slow_01` stay as they are (test and bench fixtures, offered by `run_m2`).
3. **`data/skills/skill_<id>.json`** (schema `skills.schema.json`): `kind` enum gains `guard, bounty, haste, snare, rebuild`; new optional fields `damage_factor` (guard: damage taken multiplier, 0.5), `gold_per_kill` (integer), `cooldown_factor` (haste: 0.6), `slow_factor`, `guardian_heal`, and `power_stats` (unique array of this file's numeric field names; required for every kind except `shield`). Per-kind `if/then`: `area_blast` radius, damage (unchanged); `guard` duration_sec, damage_factor; `bounty` duration_sec, gold_per_kill; `haste` duration_sec, cooldown_factor; `snare` radius, slow_factor, duration_sec; `rebuild` guardian_heal. Files (4.1): `skill_big_finish` (area_blast, radius 6, damage 40, 14 s, power `damage`), `skill_stand_firm` (guard, 6 s, 0.5, 25 s, `duration_sec`), `skill_clearance_sale` (bounty, 8 s, 4 gold, 30 s, `gold_per_kill`), `skill_crescendo` (haste, 6 s, 0.6, 25 s, `duration_sec`), `skill_tangle` (snare, radius 7, 0.15, 3 s, 18 s, `duration_sec`), `skill_emergency_rebuild` (rebuild, heal 40, 40 s, `guardian_heal`). `skill_shield` unchanged; `skill_area_blast` only gains `"power_stats": ["damage"]` (now required for its kind).
4. **`data/guardians/guardian_<waifu>.json`**: cinder, bastia, clover, hymn, tansy, poppy; hp 400, contact_radius 1.0, `skills` `[skill_<signature>, "skill_shield"]`, sprite `guardians/<waifu>`. Schema unchanged.
5. **Effect object** (shared shape, written into both `cards.schema.json` and `meta.schema.json`): `{"stat", "op", "value", "target"}`, all required. `op` enum `add, mult` (a `mult` value is the fraction added to the multiplier: -0.25 = -25%, multipliers of one stat add up, 2.5). `stat` enum = the 2.5 list (`damage, cooldown, range, hp, kill_gold, xp, build_radius, rebuild_price, detour_damage, skill_power, skill_cooldown, shield_absorb, shield_duration, shield_heal, gold, unlock_tower, unlock_level`) plus what the meta tree needs: `sell_refund`, `rebuild_fraction`, `price` (placement price). `target` pattern `^(all_towers|guardian|signature|run|tower:tower_[a-z0-9_]+|skill:skill_[a-z0-9_]+)$`: `guardian` = her max HP and all her skills, `signature` = her signature skill only (the skill cards work for every Guardian, 2.3). Unlock effects: `{"stat": "unlock_tower", "op": "add", "value": 1, "target": "tower:tower_cinder"}`, `{"stat": "unlock_level", "op": "add", "value": 4, "target": "tower:tower_pip"}`.
6. **`data/cards/<id>.json`** (new schema `cards.schema.json`; id pattern `^(card|perk)_[a-z0-9_]+$`, the 2.4 ids): `type` (enum `new_tower, signature, skill, perk, filler`), `name_key`, `desc_key`, `max_picks` (integer >= 0, 0 = unlimited, filler only), `requires` (object, both keys optional: `unlocked` = a waifu id that must be rescued in the profile, `buildable` = a waifu whose tower must be buildable this run; `{}` = always eligible), `effects` (at least 1). Files (25): `card_tower_<cinder|bastia|clover|hymn|tansy|poppy>` (requires `unlocked`, effect `unlock_tower`, max 1), `card_sig_<8 waifus>` (requires `buildable`, effect `unlock_level` 4, max 1), `card_skill_sig_power` (`skill_power` mult 0.5 `signature`), `card_skill_sig_quick` (`skill_cooldown` mult -0.25 `signature`), `card_skill_shield_plus` (`shield_absorb` mult 1.0 and `shield_duration` add 2, `skill:skill_shield`), `card_skill_mending` (`shield_heal` add 40 `skill:skill_shield`), `perk_sharp` (damage mult 0.1 all_towers, max 3), `perk_bounty` (kill_gold mult 0.2 run, max 2), `perk_study` (xp mult 0.15 run, max 2), `perk_masonry` (hp mult 0.3 all_towers and rebuild_price mult -0.5 run, max 1), `perk_expand` (build_radius add 3 run, max 2), `perk_maze` (detour_damage mult 0.2 all_towers, max 2), `card_purse` (filler, gold add 40 run, max 0).
7. **`data/synergies/syn_<tag>.json`** (new schema `synergies.schema.json`, the 5.1 format): `tag`, `kind` (enum `bff, rivals, mentor`), `name_key`, `min_distance`, `max_distance` (numbers >= 0), `bonuses` (exactly 2 items `{waifu, stat, op, value}`; tower stats enum `damage, cooldown, range, hp, slow_sec, thorns, mark_gold, aura_radius, heal`), `guardian_bonus` (`{stat, op, value}`; stat enum `shield_absorb, skill_cooldown, skill_power`). Files (7): `syn_bff_pip_mallow`, `syn_rivals_mallow_cinder`, `syn_mentor_bastia_pip`, `syn_bff_bastia_clover`, `syn_mentor_hymn_poppy`, `syn_bff_hymn_tansy`, `syn_bff_cinder_tansy`, values from 5.2 (bff and mentor 0-2.5, rivals 2-6; "+1 s" = `add 1`, "+3 thorns" = `add 3`, "+50%" = `mult 0.5`, "-20% cooldown" = `mult -0.2`).
8. **`data/meta/meta_<id>.json`** (new schema `meta.schema.json`): `name_key`, `desc_key`, `branch` (enum `economy, guardian, towers`), `cost` (integer > 0), `requires` (unique meta ids), `effects` (effect objects, item 5). Files (12, 6.2): gold_1 / gold_2 (`gold` add 50 run), kill_gold (`kill_gold` mult 0.1 run), refund (`sell_refund` add 0.15 all_towers), hp_1 / hp_2 (`hp` mult 0.1 guardian), skill_cd (`skill_cooldown` mult -0.1 guardian), xp (`xp` mult 0.1 run), tower_hp (`hp` mult 0.15 all_towers), rebuild (`rebuild_fraction` add -0.1 all_towers), radius (`build_radius` add 2 run), discount (`price` mult -0.05 all_towers).
9. **`data/runs/run_m2.json`** (schema: new required fields): `xp_base` 30, `xp_step` 30, `hearts_win` 100, `hearts_loss_min` 30, `hearts_loss_max` 50, `card_type_weights` `{"new_tower": 3, "signature": 2, "skill": 2, "perk": 2}` (all four keys required, numbers > 0). `guardian` stays until 034.
10. **`data/render/render_default.json`** (+ schema): `tower_looks` gains required `wall, aura, repair, mark, slow_area`, reusing the existing shapes with new colours (the renderer makes one batch per catalog type and looks it up by attack kind, so a missing look would break the main scene).
11. **`game/loc/strings.csv`**: every new key, English placeholder text from the docs: `waifu.<id>.name`, `tower.<waifu>.name`, `guardian.<waifu>.name`, `skill.<id>.name`, `card.<id>.name` and `card.<id>.desc` (perks included, e.g. `card.perk_sharp.name`), `syn.<tag>.name`, `meta.<id>.name` and `.desc`.

### Code
1. `tools` `tools/validate_data.py` (about +45 lines):
   - `ID_REF` prefixes gain `waifu|card|perk|syn|meta`, so `tower`, `guardian`, `requires`, `needs_card`, `bonuses[].waifu` and meta `requires` are checked by the existing dangling-reference pass.
   - effect targets: for `tower:<id>` and `skill:<id>`, the id must exist;
   - synergies: the waifus carrying `tag` in their `tags` must be exactly the two `bonuses[].waifu` (distinct);
   - skills: every `power_stats` entry is a numeric field of that file;
   - waifus: `offer_order` values unique.
2. `sim` `game/sim/tower_catalog.gd` (about +10 lines): `Attack` appends `WALL, AURA, REPAIR, MARK, SLOW_AREA` (appended, so existing values do not move; the render lookup lowercases the enum key, `SLOW_AREA` -> `slow_area`); `range`, `damage`, `cooldown_sec` read with `get(..., 0)`. Levels and the new kind fields are loaded by the tasks that use them (030-032). Until then a new-kind tower would fall into the `single` branch of `TowerAttacks`; no run offers one, so nothing changes.
